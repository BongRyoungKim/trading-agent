# Agent Teams 가이드

> 참고: https://code.claude.com/docs/en/agent-teams (공식 영문 문서), 한국어판 https://code.claude.com/docs/ko/agent-teams
> 이 문서는 웹 검색으로 수집한 공식 문서 요약과 Claude Code 설정 스키마(`teammateMode` 등)를 근거로 작성했습니다.
> 세부 문구(정확한 명령어 이름 등)는 공식 문서 원문 확인이 필요할 수 있습니다 — 실제 사용 중 동작이 이 문서와 다르면 공식 문서를 우선합니다.

## 1. 개요

Agent Teams는 여러 Claude Code 인스턴스(세션)를 조율해 하나의 작업을 함께 수행하게 하는 실험적 기능이다.

- 한 세션이 **팀 리더(team lead)** 역할을 맡아 작업을 쪼개고, 팀원에게 할당하고, 결과를 종합한다.
- **팀원(teammate)**은 각자 독립된 컨텍스트 윈도우에서 작업하며, 팀 리더뿐 아니라 서로 직접 통신할 수 있다.

## 2. Subagent와의 차이 (중요)

| 구분 | Subagent | Agent Teams |
|---|---|---|
| 통신 방식 | 메인 세션에만 결과 보고 | 리더 경유 hub-and-spoke, 팀원 간 직접 통신 가능 |
| 컨텍스트 | 결과만 부모로 반환, 대화는 휘발 | 팀원마다 독립 컨텍스트 유지, 후속 메시지로 이어서 대화 가능 |
| 적합한 작업 | 결과만 중요한 독립적 조사/검색/실행 | 논의·협업이 필요한 복잡한 다단계 작업 |
| 토큰 비용 | 낮음 | 높음 (아래 5번 참고) |

→ 결과만 필요하면 Subagent(Agent 툴), 여러 관점의 협업·병렬 개발이 필요하면 Agent Teams.

## 3. 활성화

실험적 기능이라 기본 비활성화 상태다. 환경 변수 `CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS=1`을 설정해야 한다.

이 프로젝트는 이미 `.claude/settings.json`에 다음과 같이 설정되어 있다 (2026-09-08 적용):

```json
{
  "env": {
    "CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS": "1"
  }
}
```

설정 후에는 새 세션을 시작해야 반영된다.

## 4. 팀 생성 방법

팀 구성 파일을 수동으로 작성할 필요는 없다. 대화로 자연스럽게 요청하면 Claude가:

1. 요청을 분석해 하위 작업으로 분할
2. 팀원(역할별 이름) 생성
3. 각 팀원에게 작업 할당
4. 진행 상황을 조율하고 결과를 종합

예시 프롬프트:
```
"백테스트 엔진, 리스크 관리 모듈, 대시보드를 각각 담당하는 팀을 만들어서
전략 X를 동시에 검토하고 개선안을 제안해줘"
```

## 5. 내부 구조 (참고)

- 팀 설정: `~/.claude/teams/{team-name}/config.json` — 팀원 이름, 에이전트 ID, 역할 추적
- 공유 작업 목록: `~/.claude/tasks/{team-name}/` — 모든 팀원이 읽고 쓸 수 있는 공유 태스크 트래커
- 통신: `SendMessage` 툴로 팀원 ↔ 리더, 팀원 ↔ 팀원 메시지 전달 (hub-and-spoke가 기본이지만 직접 통신도 가능)
- 종료/계획 승인 프로토콜: `shutdown_request`/`shutdown_response`, `plan_approval_request`/`plan_approval_response` 형태의 구조화 메시지로 팀원 종료 승인, 계획 승인 절차를 처리

## 6. 표시 모드 (teammateMode)

`.claude/settings.json`의 `teammateMode`로 팀원 실행 방식을 제어한다.

| 값 | 설명 |
|---|---|
| `in-process` (기본값) | 모든 팀원이 메인 터미널 안에서 실행, `Shift+Down`으로 팀원 화면 순환 |
| `tmux` | tmux가 설치되어 있으면 팀원마다 별도 pane 사용 |
| `iterm2` | iTerm2 환경에서 팀원마다 별도 창/탭 사용 |
| `auto` | 환경에 따라 자동 선택 |

```json
{
  "teammateMode": "tmux"
}
```

## 7. 비용 고려사항 (중요)

- 팀원 3명 팀은 동일 작업을 단일 세션에서 순차 처리할 때보다 대략 **3~4배**의 토큰을 소비한다 (문서에 따라 계획 모드 기준 최대 7배 언급도 있음 — 확인 필요).
- 따라서 다음 경우에만 사용을 고려한다.
  - 여러 관점의 병렬 협업이 실제로 결과 품질을 높이는 경우 (예: 코드 리뷰, 경쟁 가설 기반 버그 조사)
  - 계층이 다른 작업(백엔드/프론트엔드/테스트)을 동시에 진행해야 하는 경우
- 단순 반복 작업이나 결과만 필요한 조사는 Subagent(Agent 툴)로 충분하다.

## 8. 이 프로젝트(trading-agent)에서의 활용 예

- **전략 검증 팀**: 전략 로직 검토 담당 + 백테스트 실행 담당 + 리스크 파라미터 검토 담당을 팀으로 구성해 동시에 병렬 검토
- **인시던트 대응 팀**: 엔진 오류(logs) 분석 담당 + 거래소 API 이슈 재현 담당 + 수정 패치 작성 담당으로 분업
- **크로스 레이어 기능 추가**: 새 지표(strategy) 추가 + 백테스트 러너 연동 + 대시보드 반영을 동시에 진행

일반 버그 수정, 단일 파일 리팩토링, 간단한 조사는 Agent Teams 없이 기본 세션 또는 단일 Subagent로 처리하는 것이 비용 효율적이다.

## 9. 사용 전 체크리스트

- [ ] 작업이 정말로 "협업/논의"가 필요한가, 아니면 "결과만" 필요한가?
- [ ] 토큰 비용 3~4배를 감수할 가치가 있는 작업 규모인가?
- [ ] `.claude/settings.json`에 `CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS=1`이 설정되어 있고 세션을 재시작했는가?
- [ ] 팀원 표시 방식(`teammateMode`)이 현재 터미널 환경(tmux/iTerm2 유무)과 맞는가?
